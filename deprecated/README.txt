此目录 = 已废弃方案归档（2026-10-14）
========================================

这些文件在当前架构下【用不到】了，但保留着以防以后需要回退，所以只是
搬到这里，没有删除。

现在唯一正确的接入方式是：Trae 走公网 / HTTPS 直连服务器上的 MCP 端点。
详见上一级目录的 README.md。


----------------------------------------
隧道启动.bat                （原在项目根目录）
enable-openssh-server.ps1   （原在 server\）
----------------------------------------
废弃原因：
  这套是「SSH 隧道」方案的配套 —— 让开发机用 ssh -L 把服务器的服务端口
  转发到本地 127.0.0.1，从而不必把端口暴露在公网。

  但隧道成立的前提是「开发机能连上服务器的 22 端口」。既然 22 能连，
  那 8788 / 10087 也能直连 —— 隧道等于白折腾一层。而实测服务器上
  10087 端口本来就是开放的、公网直达，所以整条线彻底不需要。

  另外这两个文件还残留了旧默认端口 10087 与 8788 混用的历史问题。


----------------------------------------
client\  （winfile_mcp.py + mcp.config.json）
----------------------------------------
废弃原因：
  这是「本地桥接」方案：在 Trae 所在机器上跑一个 stdio 进程，由它去
  访问服务器 HTTP 接口，再转成 MCP 协议喂给 Trae。

  这套只在「Trae 版本不支持 http/sse 传输」或「网络策略禁止直连但允许
  本地进程」时才需要 —— 你的场景都不沾边，公网直连已实测全通。

注意：
  build-exe.ps1 仍会从这里取 winfile_mcp.py 编译 WinFileMcp.exe
  （dist\WinFileMcp.exe 是它的产物）。如果哪天要彻底删除本目录，
  记得把 build-exe.ps1 里那段「MCP 桥接」编译去掉，否则会报找不到源文件。
