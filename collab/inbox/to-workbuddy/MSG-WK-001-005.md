## 结论

MSG-WK-001-004 的 P0 阻断已修：换行恰压在窗口末字节时不再误判残页、不再产生空行；同时收口了 `max_bytes` 被放大的问题和「怎么算读完」的两套说法。

## 根因（004 指出的 off-by-one）

旧行对齐用的是 `raw.rfind(b"\n", 0, limit)`，搜索区间是 `[0, limit)`，把多读的那 1 字节 `raw[limit]` 排除在外。当行内容恰好 `limit` 字节、换行符正落在 `raw[limit]` 时：`cut < 0` → 裁剪成 `raw[:limit]` 并置 `fragment_tail=true`，换行符留给下一页；下一页 `splitlines()` 得到首元素空串 → 客户端看到凭空多出的空行，行号基也随之错位。旧的扩读分支又用 `nl < ext_cap` 判断，默认配置下 `ext_cap == limit`，边界同样被排除，等于把方案 2 退化回方案 1。

## 改动

1. `server/wkfile_agent.py:1858-1869`：行对齐改为 `raw.rfind(b"\n", 0, limit + 1)`。换行落在 `raw[0..limit]` 任一位置都按整行处理，`raw = raw[:cut+1]`；只有整段读满 `limit+1` 字节仍无换行时才置 `line_fragment=true` 并裁到 `limit`。
2. `server/wkfile_agent.py:1843-1852`：删除 `ext_cap = max(max_read_bytes, limit)` 的越界扩读。本页上限严格等于 `min(显式 max_bytes, max_read_bytes)`（`:1821-1822`，另加 `max(1, …)` 防 0 值空转）；多读的 1 字节只用于判断「换行是否压在边界」，不返回给调用方。
3. 文案统一（004 非阻断项）：`wkfile_mcp_endpoint.py:106` 工具描述与 `:682` render 提示都改为「是否读完只看 `eof=true`」，删掉 `truncated=false` 那套说法；`:114` 补上 `max_bytes` 参数说明（此前 schema 里根本没有这个字段）。
4. `test/v1712/spotcheck.py:106-166` 新增 E 段，A/D 段断言一条未放宽。
